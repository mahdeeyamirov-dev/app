# HabitTracker — сервер (Telegram-бот + API)

Небольшой сервер на Node.js, который:

- принимает отметки о привычках от участников через Telegram-бота;
- хранит всё в файле SQLite (`data/habits.sqlite`);
- отдаёт сводные данные по HTTP для дашборда в Mac-приложении (`GET /api/dashboard`).

## Как это работает

1. Участник открывает бота в Telegram и пишет `/start`.
2. Командой `/add <название>` добавляет себе привычку.
3. Командой `/today` открывает список своих привычек с кнопками — нажатие отмечает выполнение за сегодня.
4. `/habits` — список привычек с текущей серией дней подряд, `/delete` — удалить привычку.
5. Mac-приложение (вкладка «Дашборд») раз в какое-то время запрашивает `/api/dashboard` и показывает всех участников со всеми привычками и сериями.

## Шаг 1. Создайте бота и получите токен

1. В Telegram напишите **@BotFather**.
2. Отправьте `/newbot`, придумайте имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAExample...` — сохраните его, он понадобится ниже.

## Шаг 2. Запуск локально (для проверки)

Нужен установленный [Node.js](https://nodejs.org) (версия 20 или новее).

```bash
cd server
npm install
cp .env.example .env
```

Откройте `.env` и впишите:
- `BOT_TOKEN` — токен от BotFather
- `API_TOKEN` — придумайте любую длинную случайную строку (это пароль, которым Mac-приложение будет подтверждать доступ к дашборду)

Запуск:

```bash
npm start
```

Если всё верно, увидите `API server listening on port 3000` и `Telegram bot started`. Напишите боту `/start` в Telegram — должен ответить.

Локальный запуск работает только пока эта команда выполняется на вашем компьютере — для постоянной работы 24/7 нужно задеплоить сервер в облако (шаг 3).

## Шаг 3. Деплой в облако (чтобы бот работал круглосуточно)

Сервер — обычное Node.js-приложение с `Dockerfile`, поэтому подойдёт любой хостинг, который умеет запускать Docker-контейнеры и держать их постоянно включёнными: Railway, Render, Fly.io и подобные. Условия бесплатных тарифов у них периодически меняются, поэтому уточняйте актуальные цены на сайте выбранного сервиса перед стартом.

Общая последовательность (одинакова для большинства таких платформ):

1. Зарегистрируйтесь на выбранной платформе и подключите к ней ваш GitHub-репозиторий (или используйте их CLI для деплоя из папки `server`).
2. Укажите, что деплоить нужно папку `server` (некоторые платформы это называют "Root Directory").
3. Платформа автоматически найдёт `Dockerfile` и соберёт образ.
4. В настройках проекта добавьте переменные окружения:
   - `BOT_TOKEN` — тот же токен от BotFather
   - `API_TOKEN` — тот же секрет, что и локально
5. Подключите **постоянный диск (persistent volume)**, примонтированный в `/app/data` — иначе данные будут стираться при каждом перезапуске сервера. Название опции отличается в разных сервисах ("Volumes", "Disks", "Persistent Storage").
6. После деплоя платформа даст вам публичный адрес вида `https://ваш-проект.up.railway.app` (или похожий) — это и есть `serverURL` для настроек Mac-приложения.

## Шаг 4. Настройте Mac-приложение

1. Откройте приложение, перейдите на вкладку **«Дашборд»**.
2. Нажмите значок шестерёнки.
3. Впишите адрес сервера (без `/api/dashboard` в конце — просто `https://ваш-проект...`) и тот же `API_TOKEN`, что в `.env` сервера.
4. Нажмите «Готово», затем кнопку обновления (значок ⟳) — если всё настроено верно, появится список участников.

## Безопасность

- `API_TOKEN` — единственная защита дашборда, не публикуйте его и не коммитьте `.env` в git (он уже добавлен в `.gitignore`).
- Данные участников (имя из Telegram и отметки о привычках) хранятся только на вашем сервере.
