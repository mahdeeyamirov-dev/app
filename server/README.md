# HabitTracker — сервер (Telegram-бот + API)

Небольшой сервер на Node.js, который:

- принимает от участников числовые показатели через Telegram-бота;
- хранит всё в файле SQLite (`data/habits.sqlite`);
- отдаёт сводные данные по HTTP для дашборда в Mac-приложении.

## Как это работает

1. Участник пишет боту `/start` и сначала выбирает свою **группу**: **90-93** или **81-94**. Сменить группу можно в любой момент кнопкой «🔁 Сменить группу».
2. Затем выбирает раздел:
   - **🧱 Базовый** — общие показатели группы с фиксированным минимумом (задаются в `db.js`, константа `GROUPS`):

     | Показатель | 90-93 | 81-94 |
     |---|---|---|
     | BOOK PRO | 7 | 7 |
     | SLEEP | 2 | 1 |
     | RNK | 14 | 10 |
     | SAT | 2100 | 2100 |
     | Shield | 100 | 50 |
     | BOOK | 20 | 21 |
     | DIET | 1 | — |
     | MP3 | — | 30 |

   - **🧍 Личный** — участник сам добавляет любые свои показатели и сам задаёт минимум для каждого.
3. Потом бот показывает календарь, и участник выбирает **период**, за который вносит показатели: сначала дату начала, потом дату конца (для одного дня нужно нажать одну и ту же дату дважды). Будущие даты выбрать нельзя.
4. Нажатие на показатель предлагает ввести значение за этот период. Если значение ≥ минимума, показатель 🟢 зелёный, если меньше — 🔴 красный, если за период ничего не внесено — ⚪.
5. В личном разделе есть кнопка «➕ Добавить» (название → минимум → значение) и «🗑» для удаления.
6. Mac-приложение (вкладка «Дашборд») показывает **базовый** раздел выбранной группы: процент зелёных показателей у каждого участника. Сверху можно выбрать группу и масштаб, а стрелками ‹ › листать назад:
   - **День** — компактный список, сортировка по %;
   - **Неделя** (пн–вс) — карточки с разбивкой по каждому показателю;
   - **Месяц** — тренд по неделям месяца.

   В расчёт идёт значение, период которого пересекается с выбранным днём, неделей или месяцем. Клик по участнику открывает его карточку с графиками значений.

Значения, внесённые до появления групп и периодов, сохранены: их периодом считается день, когда их внесли. Участники без группы не видны на дашборде, пока не выберут её через `/start`.

Личный раздел — приватный, в общий дашборд не попадает.

## Шаг 1. Создайте бота и получите токен

1. В Telegram напишите **@BotFather**.
2. Отправьте `/newbot`, придумайте имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAExample...` — сохраните его, он понадобится ниже.

## Шаг 2. Запустите сервер на своём Mac

Нужен установленный [Node.js](https://nodejs.org) — скачайте LTS-версию с сайта и поставьте как обычное приложение.

Откройте **Terminal** (Программы → Утилиты → Terminal) и выполните:

```bash
cd путь/до/склонированного/репозитория/app/server
npm install
cp .env.example .env
```

Откройте файл `.env` любым текстовым редактором (например, `open -e .env` откроет его в TextEdit) и впишите:
- `BOT_TOKEN` — токен от BotFather
- `API_TOKEN` — придумайте любую длинную случайную строку (это пароль, которым Mac-приложение будет подтверждать доступ к дашборду)

Запуск:

```bash
npm start
```

Если всё верно, увидите `API server listening on port 3000` и `Telegram bot started`. Напишите боту `/start` в Telegram — должен ответить.

**Важно:** бот работает только пока это окно Terminal открыто и команда `npm start` выполняется, и только пока сам Mac включён и не спит. Закрыли Terminal или Mac ушёл в сон — бот перестаёт отвечать. Для группы, которая пишет боту в любое время, это может быть неудобно — тогда позже можно перейти на облачный деплой (шаг 3, необязательно).

## Шаг 3 (опционально). Деплой в облако, если понадобится работа 24/7

Сервер — обычное Node.js-приложение с `Dockerfile`, поэтому подойдёт любой хостинг, который умеет запускать Docker-контейнеры и держать их постоянно включёнными: Railway, Render, Fly.io и подобные. Условия бесплатных тарифов у них периодически меняются, поэтому уточняйте актуальные цены на сайте выбранного сервиса перед стартом.

Общая последовательность (одинакова для большинства таких платформ):

1. Зарегистрируйтесь на выбранной платформе и подключите к ней ваш GitHub-репозиторий (или используйте их CLI для деплоя из папки `server`).
2. Укажите, что деплоить нужно папку `server` (некоторые платформы это называют "Root Directory").
3. Платформа автоматически найдёт `Dockerfile` и соберёт образ.
4. В настройках проекта добавьте переменные окружения:
   - `BOT_TOKEN` — тот же токен от BotFather
   - `API_TOKEN` — тот же секрет, что и локально
5. Подключите **постоянный диск (persistent volume)**, примонтированный в `/app/data` — иначе данные будут стираться при каждом перезапуске сервера. Название опции отличается в разных сервисах ("Volumes", "Disks", "Persistent Storage").
6. После деплоя платформа даст вам публичный адрес вида `https://ваш-проект.up.railway.app` (или похожий) — это и есть `serverURL` для настроек Mac-приложения.

## Шаг 4. Настройте Mac-приложение

1. Откройте приложение, перейдите на вкладку **«Дашборд»**.
2. Нажмите значок шестерёнки.
3. Впишите адрес сервера:
   - при локальном запуске (шаг 2) — `http://localhost:3000`
   - при облачном деплое (шаг 3) — адрес вида `https://ваш-проект...`, без каких-либо `/api/...` в конце (само приложение допишет нужный путь)
   
   И тот же `API_TOKEN`, что в `.env` сервера.
4. Нажмите «Готово», затем кнопку обновления (значок ⟳) — если всё настроено верно, появится список участников.

## Безопасность

- `API_TOKEN` — единственная защита дашборда, не публикуйте его и не коммитьте `.env` в git (он уже добавлен в `.gitignore`).
- Данные участников (имя из Telegram и отметки о привычках) хранятся только на вашем сервере.
